1. PROJECT OVERVIEW
============================================================

Project Name
Sterling AI Recruitment Engine (AI-Powered Virtual Interview Platform)

Purpose
The primary purpose of the Sterling AI Recruitment Engine is to automate and augment technical hiring through AI-driven candidate assessment. The platform is designed to conduct dynamic, real-time, and conversational AI-based technical interviews that adapt to candidate responses, parse coding proficiency, and track behavioral intelligence. It replaces early-stage manual human interviews with a highly scalable, objective, and unbiased automated system.

Vision
To revolutionize the technical recruitment paradigm by building an intelligent system capable of engaging in human-like interactions, thereby accelerating the time-to-hire, standardizing technical evaluations, and enabling data-driven talent acquisition.

Objectives
- To conduct automated AI-based technical interviews seamlessly via web.
- To dynamically adapt question difficulty based on the candidate's real-time performance.
- To evaluate technical proficiency both natively (spoken) and syntactically (code execution).
- To track behavioral telemetry natively through web-based sensory input.
- To reduce HR workload by parsing and scoring candidate resumes automatically.
- To provide deep analytics and ranking for candidates across custom roles and departments.

Business Problem Solved
Traditional technical hiring requires significant engineering hours to screen candidates. Often, senior developers are pulled away from critical tasks to conduct preliminary interviews. Furthermore, human evaluations are prone to bias, inconsistency, and scheduling conflicts. The Sterling Assessment Engine mitigates these issues by providing asynchronous, completely automated, and highly standardized technical assessments at scale.

Industry Use Case
Ideal for enterprise engineering departments, automotive tech units (like Sterling E-Mobility), and software development agencies handling a large volume of applicant resumes and requiring strict technical vetting prior to final-round managerial interviews.

Target Users
- Technical Hiring Managers: For reviewing detailed candidate analytics and code execution results.
- HR Professionals & Recruiters: For managing job roles, screening resumes, and tracking candidate pipelines.
- Job Candidates: For undergoing a seamless, low-latency, and interactive interview experience.

Expected Benefits
- 80% reduction in preliminary technical screening time.
- 100% standardization in candidate evaluation metrics.
- Substantial cost savings in engineering man-hours.
- Enhanced candidate experience via an immersive, low-latency AI interview environment.
- Elimination of geographic and timezone bottlenecks in early-stage hiring.

Current Version
Enterprise Version 2.0 (Microservices Architecture Transition)

Platform Scope
Web-based application featuring a candidate portal, live interview engine with code workspace, and an extensive admin/HR dashboard for configuration, monitoring, and reporting.

2. EXECUTIVE SUMMARY
====================

The Sterling AI Recruitment Engine represents a paradigm shift in technical talent acquisition. Built primarily on a high-performance decoupled architecture, the platform solves the most pressing challenges in modern recruitment: scalability, evaluation consistency, and engineering time overhead.

Why this platform exists:
In the fast-paced ecosystem of tech and EV manufacturing, identifying the right talent quickly is a massive competitive advantage. Engineering teams cannot afford to spend countless hours on initial candidate screening, nor can they risk losing top-tier candidates to slow hiring pipelines. This platform exists to bridge the gap between high-volume application intake and high-quality candidate shortlisting.

Recruitment challenges solved:
- Human Bias: Every candidate receives an objective, mathematically graded evaluation based strictly on technical competence and communication.
- Scheduling Conflicts: Candidates can take the interview 24/7.
- Superficial Screening: Instead of relying purely on static resumes, candidates are evaluated on live, dynamic problem-solving.

Automation benefits:
Through end-to-end automation, from the moment a candidate registers to the final generation of a hiring report, human intervention is entirely optional. The platform automatically handles resume parsing, question generation, response evaluation, and candidate ranking.

AI interview benefits:
The AI dynamically adjusts to the candidate's proficiency. If a candidate excels, the system probes deeper into complex topics. If they struggle, it provides hints or pivots to foundational concepts. This ensures a comprehensive mapping of the candidate's true capability spectrum. 

Resume screening benefits:
Using an intelligent resume engine, the system extracts critical skills, calculates experience years, and generates an initial compatibility score. This ensures that only candidates meeting a baseline threshold are permitted to access the interview environment.

Enterprise value:
For Sterling E-Mobility, this system is an asset that standardizes quality. It acts as an infinitely scalable technical screener, ensuring that every candidate recommended for a final human interview has been rigorously vetted against Sterling’s specific technical and behavioral benchmarks.

4. SYSTEM ARCHITECTURE
======================

The platform has transitioned from a monolithic prototype to a fully decoupled, production-ready microservices architecture.

Frontend
- Framework: React 18 powered by Vite.
- State Management: React Hooks (useState, useMemo, custom hooks).
- UI/UX: Tailwind CSS with custom Z-axis glassmorphism.
- Real-time: WebSockets for bidirectional low-latency audio.
- Editor: Monaco Editor for live code execution.
- 3D Avatar: WebGL based 3D avatar rendering.

Backend
- Framework: FastAPI (Python 3.x).
- Entry Point: Main.py (Router and API gateway).
- Architecture: 20+ specialized microservices residing in the `/services` directory.
- Concurrency: Asyncio for non-blocking network I/O and WebSocket handling.
- Constraints: 15MB hard-limit on WebSocket buffers to prevent OOM.

Database
- Engine: SQLite (`database.db`) utilizing WAL (Write-Ahead Logging) for concurrent access.
- ORM: SQLAlchemy.
- Migrations/Schema: Defined in `database/models.py`.

AI Layer
- Primary LLM: OpenAI (GPT-4o) and Gemini for adaptive reasoning.
- Logic Modules: `ai_orchestrator.py`, `prompt_engine.py`, `gemini_service.py`, `openai_service.py`.

Speech Layer
- STT (Speech-to-Text): Groq API utilizing Whisper for ultra-fast, near-instant transcription (`whisper_service.py`).
- TTS (Text-to-Speech): ElevenLabs API for high-fidelity voice synthesis (`tts_service.py`).

Interview Engine
- Orchestrator: `interview_scoring.py`, `interview_memory.py`, `conversation_manager.py`.

Proctoring Layer
- WebGL tracking mocked for performance on i3 processors, managed via `useHumanBehavior.js`, backed by `behavior_analysis.py` and `eye_tracking.py`.

Reporting Layer
- Engines: `ranking_engine.py`. Generates detailed breakdown of technical, communication, behavioral, and confidence scores.

Admin Layer
- Routes and APIs dedicated to role management, question banking, and analytics dashboards.

Authentication Layer
- JWT-based authentication mapped against hashed passwords in the DB.

Architecture Flow Diagram (Text Representation):

[Candidate Browser]
   |--- (WebSockets /ws/stt) ---> [FastAPI Gateway (Main.py)]
   |                                 |---> [Whisper Service (Groq API)] --> (Transcript)
   |                                 |---> [Prompt Engine & Context Injector]
   |                                 |---> [OpenAI/Gemini Evaluation]
   |                                 |---> [TTS Service (ElevenLabs)]
   |<-- (Audio Stream Buffer) -------|
   |
[Monaco Editor] ---> (Code Sync) ---> [Backend Context Merger]
   |
[Admin Dashboard] <--- (REST APIs) ---> [Database (SQLite WAL)]

5. FRONTEND ANALYSIS
====================

The frontend is a React-based SPA built with Vite, emphasizing high-performance rendering and a premium SEM-inspired aesthetic.

React Components
- `App.jsx`: Main application wrapper configuring React Router.
- `Avatar3D.jsx` & `AvatarRig.jsx`: Components responsible for rendering the 3D interviewer persona and handling lip-sync animations synchronized with incoming audio.

Pages
- `Landing.jsx`: The public face of the platform.
- `Login.jsx`: Secure gateway for candidates and administrators.
- `Dashboard.jsx`: The HR/Admin command center displaying system-wide analytics.
- `CandidateDetails.jsx`: Detailed view for recruiters to analyze a specific applicant.
- `LiveInterview.jsx`: The core interactive engine handling webcam, microphone, avatar, and code editor.
- `Report.jsx`: Post-interview candidate summary and grading view.
- `AdminPanel.jsx`: Configuration management for roles, departments, and questions.

Routes
Standard client-side routing utilizing `react-router-dom` v7 to navigate between the aforementioned pages.

State Management
Relies heavily on native React Hooks (`useState`, `useEffect`, `useRef`). Extensive use of `useMemo` within `LiveInterview.jsx` prevents unnecessary render loops when handling high-frequency WebSocket updates.

UI Design & Theme System
Adopts a futuristic, dark-mode "glassmorphism" aesthetic. Tailwind CSS handles layout and utilities, while `index.css` dictates custom Z-axis styling, glows, and shadow drops to match Sterling E-Mobility's premium brand identity.

Responsive Design
The layout adapts to various screen sizes, though the Live Interview environment is optimized for desktop usage to accommodate the code workspace and video feeds simultaneously.

Custom Hooks
- `useAudioRecorder.js` / `useWebSocketSTT.js`: Manage chunked audio capturing (500ms intervals) and WebM blob transmission over WSS.
- `useVAD.js`: Voice Activity Detection to intelligently pause/resume listening.
- `useCodeWorkspace.js`: Synchronizes Monaco editor state.
- `useAvatarState.js` / `useAvatarLipSync.js`: Map audio frequency data to 3D mesh morph targets.

6. BACKEND ANALYSIS
===================

The backend is built on FastAPI, chosen for its native asynchronous capabilities and exceptional performance in handling WebSockets.

FastAPI Structure
- `Main.py`: The central monolith that has been aggressively refactored. It holds the core API routes, WebSocket endpoints (`/ws/stt`), and acts as the delegator to the microservices.

Controllers & Services
The backend relies on the `/services` module pattern. 
- `ai_orchestrator.py`: Coordinates the flow between transcription, reasoning, and speech synthesis.
- `resume_engine.py`: Handles complex PDF parsing, skill extraction, and scoring against role profiles.
- `prompt_engine.py`: Contains advanced prompt templates to prevent LLM hallucination and manage "small talk" natively.
- `circuit_breaker.py`: Ensures system stability during external API outages.
- `confidence_engine.py`: Analyzes linguistic markers for confidence scoring.

Middleware
CORS middleware is configured to allow frontend communication. 

Authentication & Authorization
JWT token validation securing admin routes and candidate-specific endpoints.

Interview APIs
Endpoints managing session initialization, state transitions (StatusLookup tracking), and interview termination.

Resume APIs
File upload endpoints processing multipart/form-data, extracting text, and generating the `resume_score`.

Analytics APIs
Aggregates data across `JobRole`, `InterviewSession`, and `FinalReport` tables to feed `Dashboard.jsx`.

Error Handling & Logging
Robust try-catch blocks within WebSocket streams to gracefully handle disconnection (`WebSocketDisconnect`) without crashing the event loop.

7. DATABASE ARCHITECTURE
========================

The platform uses a highly normalized relational SQLite database with SQLAlchemy ORM.

1. Department
- Purpose: Groups job roles.
- PK: `department_id`
- Relationships: 1:N with JobRole, 1:N with QuestionBank.

2. JobRole
- Purpose: Defines specific positions (e.g., Firmware Engineer).
- PK: `role_id`, FK: `department_id`
- Fields: `persona`, `tech_weight`, `comm_weight`, `eq_weight`, `conf_weight`.
- Relationships: 1:N with InterviewSession, QuestionBank.

3. Candidate
- Purpose: Stores user identities.
- PK: `candidate_id`
- Fields: `name`, `email`, `password_hash`.
- Relationships: 1:N with Resume, InterviewSession, CandidateAnswer, FinalReport.

4. Resume
- Purpose: Stores parsed resume metrics.
- PK: `resume_id`, FK: `candidate_id`
- Fields: `extracted_text`, `skills_detected`, `experience_years`, `resume_score`.

5. InterviewSession
- Purpose: Tracks the lifecycle of an interview.
- PK: `interview_id`, FK: `candidate_id`, `role_id`, `status_id`.
- Fields: `duration_seconds`, `overall_score`, `technical_score`, `communication_score`.
- Relationships: Central hub linking to answers, evaluations, and reports.

6. QuestionBank
- Purpose: Central repository for all AI-askable questions.
- PK: `question_id`, FK: `department_id`, `role_id`
- Fields: `question_text`, `difficulty`, `keywords`.

7. InterviewQuestionsLog
- Purpose: Tracks exactly which questions were asked in which order during a session.
- PK: `asked_question_id`, FK: `interview_id`, `question_id`.

8. CandidateAnswer
- Purpose: Stores raw responses and timings.
- PK: `answer_id`, FK: `candidate_id`, `interview_id`, `question_id`.

9. KeywordEvaluation & QuestionEvaluation
- Purpose: Stores granular scoring per question based on keyword matching and AI sentiment.

10. UnifiedInterviewData
- Purpose: A denormalized aggregate of questions, answers, and evaluations for rapid report generation.

11. ConversationHistory
- Purpose: Verbatim transcript log of the entire interaction (Speaker: AI vs Candidate).

12. FinalReport
- Purpose: The ultimate HR summary document.
- PK: `report_id`, FK: `candidate_id`, `interview_id`
- Fields: `overall_score`, `grade`, `strengths`, `weaknesses`, `hiring_decision`.

8. CANDIDATE WORKFLOW
=====================

1. Registration & Login: Candidate creates an account securely.
2. Resume Upload: Candidate uploads a PDF resume.
3. Resume Analysis: `resume_engine.py` extracts text, detects skills, matches against the JobRole, and assigns a baseline `resume_score`.
4. Readiness Check: System verifies AV peripherals (mic, camera).
5. Interview Launch: Candidate enters `LiveInterview.jsx`. WebSocket connection established.
6. Introduction: AI Avatar greets candidate (handling small talk securely).
7. Question Generation: System pulls questions mapped to the role, adapting based on live performance.
8. Answer Submission: Candidate speaks (STT via Whisper) and optionally writes code in Monaco.
9. Evaluation: `openai_service.py` evaluates the transcript + code block against expected keywords.
10. End Interview: Session gracefully terminates.
11. Report Generation: `ranking_engine.py` compiles all evaluations into a FinalReport.
12. Dashboard Updates: HR instantly sees the new candidate data.

10. RESUME SCREENING ENGINE
===========================

Implemented natively in `resume_engine.py`.

- Resume Parsing: Extracts raw text from uploaded PDFs.
- Skill Detection: Uses NLP to identify core competencies.
- Experience Detection: Estimates YOE (Years of Experience) from timeline markers.
- Keyword Extraction: Matches text against a predefined lexicon.
- Scoring Logic: Generates a `resume_score` (out of 100) based on alignment with the applied JobRole's requirements.
- Role Matching: Filters out aggressively unqualified candidates.
- Fallback Mechanism: Defaults to raw text analysis if advanced parsing fails due to complex PDF formatting.

---

============================================================
11. AI INTERVIEW ENGINE
=======================

The core cognitive brain of the system, leveraging multiple microservices.

- Question Selection: Pulled dynamically from `QuestionBank` or generated procedurally by LLM based on context.
- Role Mapping: LLM instructions are tightly bound to the `JobRole.persona`.
- Context Memory: Maintained via `interview_memory.py`, ensuring the AI remembers previous answers to prevent repetition and allow call-backs.
- Follow-Up Logic: If an answer lacks depth, the `prompt_engine.py` instructs the AI to probe specifically into the missing technical keywords.
- Code Context Injection: Monaco editor content is prepended to the spoken transcript, allowing the LLM to "see" what the candidate typed.
- Decision Making: Orchestrated by `ai_orchestrator.py`.
- Neutral Terminology: Hardcoded instructions inside prompt wrappers ensure the AI refers to itself as the "Sterling Assessment Engine" and never reveals its underlying provider (OpenAI/Gemini).

---

============================================================
12. SPEECH & AVATAR SYSTEM
==========================

- Speech Recognition: 500ms audio chunks streamed via WebSockets to Groq Whisper for sub-second latency STT. Memory is aggressively managed with a 15MB buffer limit.
- Speech Synthesis: Handled by ElevenLabs via `tts_service.py`. The system bypasses disk writing by directly streaming the audio buffer to the frontend's HTML5 Audio context.
- Avatar Rendering: React Three Fiber / WebGL implementation in `Avatar3D.jsx`.
- Lip Sync: `useAvatarLipSync.js` maps audio frequencies and visemes to morph targets on the 3D model, creating a highly realistic visual representation of speech.
- Performance Optimization: Extensive `useMemo` caching to prevent React render cycles from dropping 3D frame rates.

---

============================================================
13. PROCTORING SYSTEM
=====================

Designed to ensure assessment integrity.

- Face Detection & Eye Tracking: Implemented in `eye_tracking.py` and `behavior_analysis.py`.
- Tab Monitoring: The frontend listens for `visibilitychange` events to detect if the candidate leaves the interview tab.
- Focus Tracking: Tracks cursor movement and window blur events.
- Suspicious Activity Detection: Flags anomalies in the `FinalReport`.
- Optimization Note: Heavy client-side WebGL inference was deliberately mocked (`useHumanBehavior.js`) to ensure stability on lower-end devices (e.g., i3 processors), delegating heavier analysis to the backend.

14. QUESTION BANK MANAGEMENT

- Question Storage: Stored in the `question_bank` SQLite table.
- Categorization: Mapped strongly to `department_id` and `role_id`.
- Difficulty Levels: Labeled (Easy, Medium, Hard) to allow dynamic scaling during the interview.
- Keywords: Critical `keywords` field used by `KeywordEvaluation` to mathematically verify if a candidate touched on necessary concepts.
- Import Workflow: Scripts and APIs exist to ingest CSVs.

============================================================
15. SECURITY ARCHITECTURE
=========================

- Authentication: Passwords heavily hashed (`password_hash` in `Candidate`).
- API Protection: Role-based access control preventing candidates from hitting admin routes.
- Input Validation: Pydantic models validate all incoming FastAPI requests.
- SQL Injection Protection: Fully mitigated via SQLAlchemy ORM parameterized queries.
- CORS Security: Strict origins defined in FastAPI middleware.
- Memory Security: 15MB hard-limit on WebSocket buffers prevents malicious buffer overflow/OOM attacks.

============================================================
16. PERFORMANCE OPTIMIZATION
============================

- Database Optimization: SQLite configured with WAL (Write-Ahead Logging) mode, allowing concurrent reads and writes, solving database locking issues.
- Frontend Optimization: `React.useMemo` and strict dependency arrays prevent cascading re-renders in the `LiveInterview.jsx` component.
- API Optimization: Microservices pattern isolates heavy LLM calls from the main thread via Asyncio.
- Audio Optimization: True streaming of ElevenLabs TTS buffers completely eliminates disk I/O latency.
- State Management: Removed tight loops in the UI related to the 3D Avatar state.
